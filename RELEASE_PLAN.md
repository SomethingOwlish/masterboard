# План доведения Masterboard до беты

Обновлён 21 сентября 2026. Базовая проверка — реальные пользовательские маршруты,
а не наличие реализации в исходниках или отдельном стенде.

## 1. Рабочие сессии и доска — выполненный первый блок

- [x] Добавлять объекты библиотеки на сцену кнопкой и перетаскиванием.
- [x] Перемещать сцены свободно; менять размеры; перемещать карточки внутри сцены.
- [x] Переносить карточку между сценами; использовать один объект в разных сценах.
- [x] Соединять сцены стрелками; менять порядок игры отдельно от координат.
- [x] Сохранять позиции, размеры, состав и переходы после перезагрузки.
- [x] Сохранять доску в архиве и резервных копиях; выводить SVG-схему в печати.
- [x] Использовать один компонент доски на стенде и в реальной кампании.
- [x] Сохранить старые списки сцен: координаты по умолчанию, без сброса материалов.

Приёмка в браузере: создана отдельная QA-кампания; добавлен NPC; созданы сцены;
мышью изменены расположение и размер сцены, NPC перенесён между сценами и
перетащен из библиотеки; создан переход; после reload проверены состав и схема.
Автотесты дополнительно покрывают архив, backup, неверные координаты и удаления.

Оставшаяся проверка этого блока: реальные мобильные устройства, длительная
сессия с большим количеством объектов, экспорт браузером в PDF. Свободное
рисование/наклейки старого планировщика пока не переносились.

## 2. Единый сценарий сессии

- [x] Подключить к одной модели подготовку, игровой стол и разбор результатов.
- [x] Показывать в игровом столе связанные со сценой объекты и данные карточек.
- [x] Дать переходить между сценами по графу; сохранять текущую сцену и журнал.
- [x] Добавить дату, независимые документы сессий, несколько будущих сессий,
  дублирование и безопасное удаление. Архив не должен зависеть от текущего плана.
- Проверить три последовательные игры, две будущие сессии, возврат в архив,
  печать любой сессии, закрытие/повторное открытие браузера.

Проверено в браузере: создание будущей игры с датой во время текущей; возврат
к текущей игре; журнал, завершение и итоги; корзина, восстановление и reload;
копирование завершённой доски с материалами и стрелками.

Критерий: вся кампания ведётся через пользовательский интерфейс, без обращения
к `/demo/*`, подмены данных или ручного редактирования storage.

- [x] Единый вывод полей в библиотеке, игровом столе и печати; ссылки на сессии,

- Изображения персонажей, NPC и локаций.
- Полноценные связи и обратные ссылки; единые карточки в библиотеке/сценах/печати.

- Правила: markdown, поиск, оглавление. Настройки типов Misc.

Критерий: создать данные один раз, использовать на сценах и видеть изменения
везде; удаление не оставляет необъяснимых пустых карточек.

## 4. Долговечное хранение и интеграции

- Зафиксировать целевой backend: исходное DESIGN.md описывает GitHub + IndexedDB;
  более поздние модели репозиториев допускают другую архитектуру.
- Сделать миграцию localStorage с резервной копией и проверкой сохранённых объектов.
- Долговечная очередь изменений, повтор после сбоя/перезапуска, конфликты и
  понятное состояние синхронизации; серверная проверка доступа при совместной работе.
- Подключить импорт сайтов и внешний трекер задач к тем же рабочим сущностям.

Критерий: offline → изменения → перезапуск → online не теряет и не дублирует данные;
ошибка одного модуля не повреждает остальные. Проверить на выделенном тестовом репозитории.

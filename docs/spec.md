## 0. Сквозные требования

### 0.1 Хранение
- ✅ Все данные кампании хранятся в IndexedDB (`IdbStorageGateway`, база `masterboard-documents`), по документу на кампанию: `localCampaigns/{id}`. Старые данные из `localStorage` переносятся один раз, исходная строка остаётся в `masterboard.local-campaigns.v1.backup`.
- ✅ Повреждённые данные **не удаляются**: исходная строка сохраняется в резервный ключ, пользователь видит баннер с кнопкой «Скачать резервную копию».
- ✅ Экспорт/импорт кампании одним JSON-файлом (ручной бэкап до появления интеграций).
- ✅ Идентификаторы создаются через общий генератор (`src/model/ids.ts`), без коллизий при создании двух объектов в одну миллисекунду.
- ✅ Изменение сохраняется в фоне; при ошибке оно остаётся на экране, появляется сообщение и кнопка «Повторить».

### 0.2 Единая модель сессии
- ✅ Устаревшие поля `firstSession*` мигрируются в `sessionRecords` и удаляются из записи кампании; после миграции единственный источник — `sessionRecords`.
- ✅ Признак «кампания готова» не зависит от количества заметок: удаление последней заметки не возвращает пользователя в онбординг.

### 0.3 Навигация
- ✅ Навигация кампании (общая для дашборда и сессий) содержит все разделы: Обзор, Сессии, Сюжет, Пульт, Библиотека, Связи, Заметки. Печать добавится на этапе 3.
- ✅ Неизвестный `section` ведёт на Обзор, а не на пустую страницу.
- ✅ Мёртвый код удалён: `LocalLiveSession.tsx`, недостижимые ветки `LocalSessionContext` / `LocalSessionReview` в `LocalNewCampaignPage.tsx`.

### 0.4 Качество
- 🟡 Для каждой области ниже есть unit-тесты на логику каталога (`src/fixtures/localCampaignCatalog.test.ts` или отдельные файлы).
- ✅ Testing Library + jsdom подключены; сценарии интерфейса — `src/pages/localCampaign.ui.test.tsx`.

## 1. Кампания и со-мастер

| Требование | Статус |
|---|---|
| Создание, паспорт (название, идея, активное время), редактирование | ✅ |
| Мастера кампании как список, а не свободная строка `"Сова + Лис"` | ⛔ |
| Роль **владелец** (один) и **со-мастер** (0..n) | ⛔ |
| **Ответственный мастер** сессии выбирается из списка мастеров кампании | 🟡 (свободный текст) |
| Передача ответственности за сессию с записью в журнал | ⛔ |
| Архивация / удаление кампании с подтверждением | ⛔ |
| Витрина «Лунный порт» в списке ведёт в `/local`, а не в `/demo` | ✅ |

**Модель:** `masters: { id, name, role: 'owner' | 'co-master' }[]`; `session.masterId`.
**[Решение D2]** Роли — только подписи или ограничения прав (готовая логика: `storage/campaignDocuments.ts → canManageCampaign`).

**Приёмка:** создать кампанию → добавить со-мастера → назначить его ответственным за сессию → передать ответственность обратно; все изменения переживают перезагрузку.

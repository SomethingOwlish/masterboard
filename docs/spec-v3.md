## Общие правила для каждого этапа

- Перед началом прочитать этот раздел и свой этап. В начале чата — `npm run typecheck && npm test`, чтобы
  знать исходное состояние.
- Не выходить за рамки этапа. Замеченное по пути — в раздел «Найдено по ходу» в конце документа.
- К каждому исправленному дефекту — тест (unit в `src/local/*.test.ts` или сценарий в `src/pages/*.ui.test.tsx`).
- Новый JSX не писать в одну строку: один элемент верхнего уровня на строку, длинные пропсы — переносом.
- В конце: `npm run typecheck && npm run lint && npm test` зелёные. Отметить этап ✅ здесь, дописать
  PR в «Журнал».
- Номера строк ниже — на `de384a7`. Ориентироваться по названиям функций, строки могли сдвинуться.

### Этап 12 — Разбор с применением в конце (В2) ⛔
- Шаги 3–4 пишут в черновик разбора (`session.reviewDraft`: часы ±, прогресс арок, игровое время, смена статуса секретов), не в кампанию.

### Этап 14 — Заметки как сущности (В4) ⛔

- «В заметку» из входящих создаёт сущность `note`.
- **Приёмка:** старая кампания со строками заметок после загрузки показывает их в разделе и в библиотеке; экспорт/импорт сохраняет.

## Найдено по ходу

- **Этап 1 → мост (lorebridge):** «Оставить как в КК9» может запомнить страницу, только если мост отдаёт
  `current.fingerprint` в ответе 409. Клиент уже его принимает; просьба записана в
  `docs/contracts/lorebridge-masterboard.md`. Пока моста нет — честное сообщение «Следующая отправка снова спросит».
- **Этап 1:** у режимов play/review нет отдельного пункта в навигации сессий — подсветка режима переносится
  в этап 11 (раскладка проведения); сейчас кнопки ведут к панели и ставят на неё фокус.
- **Этап 1 (поведение):** «Завершить разбор» без переносов теперь по умолчанию создаёт следующую сессию
  (или берёт уже созданную); есть вариант «Пока не создавать».
- **Этап 1 (вёрстка):** кнопки в шапке сессии переносятся под заголовок, а не сжимают его в колонку.
- **Этап 0:** `package-lock.json` расходился с `package.json` (`npm ci` падал: нет вложенного `esbuild@0.28.2`
  для `vitest`) — lock обновлён `npm install`, версии прямых зависимостей не менялись.
- **Этап 2 (решения):** сессии в корзине не мешают удалить сущность — её пункты там становятся текстом с её
  именем. Архивная сущность на графе видна, пока на неё ведёт показанная связь (пунктир, «в архиве»).
  Закрытый без решения диалог заполненных часов не меняет их; кнопка «Подтвердить срабатывание» видна у
  заполненных нерешённых часов, а не только у «Ждут подтверждения».
- **Этап 2:** «Где используется» в Библиотеке так же писал `activeSessionId` — переведено на `?session=<id>`.
- **Этап 2 → этап 15:** подпись `⌘K` на macOS уже сделана здесь (`searchShortcut` в `peekContext.ts`).
- **Этап 2 (поведение):** при смене типа в редакторе значения полей, которым нет места в новом типе, видны в
  блоке «Из основы» под своими подписями (как при пакетной смене типа), а не пропадают.
- **Этап 0:** dev-окружение — `env.dev` в `wrangler.jsonc`; wrangler не наследует привязки в окружение, поэтому
  D1 и `LOREBRIDGE` там повторены — при смене `database_id` или сервиса править оба места.
- **Этап 3 (решения):** отвязка или смена мира/стола блокирует все неотправленные элементы туда, включая
  подтверждённые (подтверждение снимается), с причиной «Подключение отвязано от кампании». Подключили то же
  снова — «Проверить черновики» пересматривает их как обычные черновики. `sendConfirmed` дополнительно
  блокирует элементы на отвязанное подключение (правка со-мастера, старая копия) и сообщает «Заблокировано: N».
- **Этап 3:** «Проверить» на карточке интеграции — только у владельца (итог пишется в кампанию, как и сама связь).
  Итог хранится в `CampaignLink.checkedAt` + `checkError` (нет ошибки — проверка прошла).
- **Этап 3 (падежи):** кроме предложного, в мастере был творительный «Проверяем связь с Лорбук» — теперь
  «Проверяем, отвечает ли Лорбук…». «По правилам: N сущностей ещё не отправлены» не согласовывалось с числом —
  теперь «По правилам: N сущность/сущности/сущностей — новые или изменённые…».
